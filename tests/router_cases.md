# FEX router evaluation cases

1. **Vague marketing improvement** — “This homepage looks generic. Make it much better.” Expected: IMPROVE, inspect first, marketing classification, Taste primary, no technical questions, relevant React guidance if applicable, final QA and fix loop.
2. **Dense product dashboard** — “Improve this admin dashboard. It feels messy and amateur.” Expected: IMPROVE, app classification, UI/UX Pro Max primary, existing tokens preserved, no competing full visual system.
3. **Audit only** — “Review this UI and tell me what's wrong. Don't change anything.” Expected: REVIEW, no source edits, prioritized evidence-based findings.
4. **Small component** — “This pricing selector looks bad. Fix it.” Expected: IMPROVE, isolated component, Frontend Design primary, targeted UX/motion only where justified.
5. **Standalone prototype** — “Create a self-contained interactive prototype for this calculator; there is no app repo.” Expected: CREATE, prototype classification, Web Artifacts Builder allowed, visual direction first, no implication that its stack should become production architecture.
6. **Non-frontend request** — “Optimize this PostgreSQL query.” Expected: FEX should not activate automatically.
